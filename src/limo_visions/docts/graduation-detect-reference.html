纯视觉黄色道路线检测节点 graduation_lane_detector：只做检测，不发速度指令。每收到一帧图像，完成一次分割、跟踪、定位和发布，结果交给 graduation_control.py。

每帧处理流程（callback）

实际调用顺序：分割 → 跟踪 → 更新状态 → 定位目标列 → 投影 → 搜索方向 → 发布 Pose → 右侧点 → 掩膜。跟踪像素数和最远端行号也直接写进 Pose。

图像中的各个区域

画面第 320 行以下被车身挡住，所以跟踪窗口虽然设到第 475 行，实际起作用的只有 240–320 这 80 行，对应车前约 0.95–1.6 m。

目标列参考行按 320, 310, 330, 300, 340, 350, 290, 360, 280, 370, 270, 260, 250 的顺序尝试，330 以下的行在当前仿真里被遮挡，自然跳过。

右侧线在 250–320 行、每隔 6 行取样一次，共 12 行。

搜索方向 ROI 位于遮挡区
side_hint ROI（行 360–460）在当前仿真中总是黑的，所以 position.y 恒为 340。控制节点持续丢线时因此总是向右搜索，这正符合顺时针赛道的需要。

各方法详解

extract_features：光照自适应黄色分割 已调好，无需改

1. 取近场路面（行 280–480、列 0–400）的平均灰度 mean_l。

2. 按 mean_l 查 7 档 Gamma 表（10/20/35/55/80/110/∞ → 0.20…1.00），Gamma < 1 时查表增亮。

3. HSV [13,50,30]–[35,255,255] 限定黄色色相与饱和度，排除白色标线。

4. LAB [0,118,138]–[255,150,255] 排除草坪和灰色路面；两者取交集。

5. 3×3 开运算去噪点，5×5 闭运算连接细小断裂。

6. 第 200 行以上清零，返回 0/255 单通道掩膜。

gamma = next(g for upper, g in self.gamma_table
             if mean_l < upper)
boosted = cv2.LUT(cv_image, self.gamma_lut[gamma]) \
          if gamma < 1.0 else cv_image
mask = cv2.bitwise_and(inRange(hsv, ...),
                       inRange(lab, ...))
mask = morphologyEx(mask, MORPH_OPEN, 3x3)
mask = morphologyEx(mask, MORPH_CLOSE, 5x5)
mask[:self.roi_top_row] = 0
sliding_window_tracking：锁定目标黄线

1. 对跟踪范围（行 240–475、列 10 起）做列统计 hist。

2. 候选列：hist ≥ max(6, 0.05 × 最高列)，过滤孤立噪点。

3. 预测位置 prior_x = 上一帧列 + 平滑速度。

4. 未锁线：权重 = 支持像素 / (1 + 距离 / 35)，取最大者（初次选线，偏向靠近 115 的线）。

5. 已锁线：只保留离预测位置 130 px 以内的候选，取“距离 − 0.05 × 支持像素”最小者。

6. 从起始列开始自底向上走 9 个窗口（高 26 px、半宽 65 px），窗口内像素 > 15 时用均值重新定位。

7. 窗口偏空时，在同一行带内找离当前列 65 px 以内的像素，取中位数续接。

锁线半径让跟踪不会跳到建筑黄框或右侧道路线；过缺口时右侧线在 130 px 之外，被排除。

prior_x = last_valid_x_px + last_valid_x_velocity
if track_confirmed:
    cand = cand[|cand - prior_x| <= 130]
    score = |cand - prior_x| - 0.05 * hist[cand]
    current_x = cand[argmin(score)]
else:
    w = hist[cand] / (1 + |cand - prior_x| / 35)
    current_x = cand[argmax(w)]

for window in range(9):      # 自底向上
    good = 窗口内像素
    if len(good) > 15:
        current_x = mean(x[good])
    else:
        current_x = median(同行带内 ±65 px 的像素)
update_track_state：锁线状态与速度估计

1. 跟踪像素 < 25：视为本帧跟踪失败，失败计数 +1；连续超过 60 帧才放弃锁线；速度估计减半。

2. 否则：计数清零、置为已锁线。

3. 取最靠近画面底部 12 行内像素的中位数作为新列。

4. 速度 = 0.5 × 本帧变化（限幅 ±60 px/帧）+ 0.5 × 旧速度。

if num_pts < 25:
    lost_frame_count += 1
    if lost_frame_count > 60:
        track_confirmed = False
    velocity *= 0.5
    return
new_x = median(底部 12 行内的 x)
raw = clip(new_x - last_x, -60, 60)
velocity = 0.5 * raw + 0.5 * velocity
last_x = new_x
locate_target_column：按参考行取目标列

依次尝试 13 个参考行，第一个在 ±6 px 行带内有目标黄线像素的行，取这些像素列的中位数，返回 (列, 行)；全部没有则返回 (-1, -1)，表示丢线。

末尾的 270 / 260 / 250 是远处兜底行：左拐时车为了不切弯转得晚，黄线会先从近处几行的画面左侧移出，这时用远处的列继续转向。缺口处远端也没有黄线，所以缺口仍会被识别为丢线。

pixel_to_ground：像素投影到地面
ray_y = -(u - 320.5) / 381.36
ray_z = -(v - 240.5) / 381.36
fwd   = cos(p) + ray_z * sin(p)
down  = sin(p) - ray_z * cos(p)
scale = 0.385 / down
前方 = 0.1848 + scale * fwd
左侧 = scale * ray_y          # p = 0.2618 rad

内参来自 /color/camera_info，安装位姿来自 URDF，离地高度用深度图实测。换相机或安装位置必须同步修改。例：目标列 115 在第 320 行对应左侧约 0.45 m。

compute_side_hint：丢线搜索方向辅助量

在 ROI（行 360–460、列 270–320）内找含黄色像素的行，返回最上与最下行的中点；没有像素时返回 340（y0 − 20）。数值越小说明越缺黄色，控制节点会转向找线。

find_right_points：右侧黄线地面点

1. 对整张掩膜做 8 连通域标记，与目标黄线像素相连的连通域全部排除。

2. 只在目标黄线也出现的取样行（250–320，每 6 行）里找。

3. 该行目标黄线列右侧 60 px 以外，离它最近的其余黄色像素。

4. 投影到地面，放进 Polygon（x = 前方，y = 左侧，m）。

排除连通像素是因为：弯道处左侧黄线会绕过画面，在同一行的右侧再出现一次，不排除就会把外侧线误当成右侧线，右侧保护就会在弯道里错误地拦住转向。
